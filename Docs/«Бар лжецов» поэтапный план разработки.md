# «Бар лжецов»: поэтапный план разработки

Nov 19, 2026 · @Saylas

MVP собирается за 19 этапов в 3 дня. Каждый этап заканчивается проверяемым результатом, а каждый день — рабочей WebGL-сборкой. Основа — документ «MVP «Бар лжецов»: план на 3 дня»: Unity 6, ядро на чистом C#, офлайн с ботами, hot-seat и онлайн на Photon PUN 2, русская рулетка с револьвером.

## День 1 — ядро и играбельный офлайн

### Этап 0. Подготовка проекта (0,5 ч)

- [ ] Проект Unity 6000.6.3f1, шаблон 2D, модуль WebGL, Build Target → Web.
- [ ] Папки `Assets/_Project/{Core, Core.Tests, Application, Networking, Presentation, Infrastructure, Bootstrap, Content}` и asmdef на каждую. У `Core` — `noEngineReferences: true`.
- [ ] Пакеты: TextMeshPro, Newtonsoft Json, DOTween, Photon PUN 2 — FREE, Unity Test Framework.
- [ ] Сцена `Boot` с пустым `Bootstrap` (Composition Root).
- [ ] Git: Unity `.gitignore`, первый коммит, репозиторий на GitHub.
- [ ] Начать учёт времени (идеи и реализация отдельно).

**Готово, когда:** проект собирается без ошибок, ссылки между asmdef идут только внутрь (Presentation/Networking → Application → Core).

### Этап 1. Смоук-тест Photon в WebGL (1 ч)

- [ ] Регистрация в Photon, AppId PUN, фиксированный регион в PhotonServerSettings.
- [ ] Тестовая сцена: подключение, кнопки «Создать» / «Войти» с полем кода, список игроков в комнате, кнопка «Пинг», которая шлёт `RaiseEvent` и показывает ответ.
- [ ] WebGL-сборка → скрытая страница itch.io (Gzip + Decompression Fallback).
- [ ] Проверка: 2 вкладки + телефон на мобильном интернете.

**Готово, когда:** три клиента видят друг друга и обмениваются сообщениями. **Не работает** (нет подключения из РФ, PUN 2 не собирается под Unity 6) → этапы 13–16 вычёркиваются, день 3 уходит на полировку, онлайн описывается в документе как следующий шаг. Тестовую сцену сохранить — на этапе 13 она станет основой `RoomService`.

### Этап 2. Домен ядра (1 ч)

- [ ] `Fact` (Id, Text, IsTrue, Explanation, Difficulty), `Subject` (Id, Title, Facts).
- [ ] `Hand`: список карт, `Remove(ids)`, `Contains`, `IsEmpty`.
- [ ] `Revolver` (BulletIndex, Shooted, `Shot()`): 6 камор, пуля в случайной каморе; `Shot()` возвращает `true`, если `Shooted == BulletIndex`, и увеличивает `Shooted`.
- [ ] `PlayerState` (SeatId, Name, Hand, Revolver, IsAlive, Stats), `TablePlay`, `MatchState`, `MatchPhase`.
- [ ] `GameRulesConfig` как обычный C#-класс (ScriptableObject-обёртка будет в Infrastructure), `IRandom` + `SeededRandom`.
- [ ] Тесты: `Revolver` стреляет ровно на каморе с пулей, выстрел гарантирован не позже 6-го нажатия; `Hand.Remove` не удаляет чужие карты.

**Готово, когда:** домен компилируется без ссылок на `UnityEngine`, тесты зелёные.

### Этап 3. Движок правил (2 ч)

- [ ] Действия: `IGameAction`, `PlayCardsAction`, `CallLiarAction`.
- [ ] События: `RoundStarted`, `CardsPlayed`, `LiarCalled`, `FactsRevealed`, `RevolverShooted`, `PlayerEliminated`, `TurnChanged`, `MatchEnded`.
- [ ] `Dealer`: размер руки по числу игроков (5 / 4 / 3), в каждой руке минимум 1 ✓ и 1 ✗.
- [ ] `TurnOrder`: следующий живой с картами; флаг принудительного обвинения, когда карты остались только у сыгравшего.
- [ ] `AccusationResolver`: хотя бы одна ✗ → стреляет сыгравший, иначе — обвинивший.
- [ ] `IActionRule`: `IsPlayersTurn`, `CardsInHand`, `CardCountInRange`, `CanCallLiar` (нельзя на первом ходу раунда), `ForcedAccusation`.
- [ ] `MatchEngine.Start(settings)` / `Apply(action)` → `ApplyResult` (успех + список событий или ошибка валидации).
- [ ] `MatchState.SnapshotFor(seatId)` → `PlayerView` (публичное + своя рука с пометками).
- [ ] Тесты: раздача на 2 и 6 игроков; обвинение верное и неверное; принудительное обвинение; выбывание после выстрела; кто начинает новый раунд; конец партии; чужие руки не попадают в `PlayerView`; невалидное действие не меняет состояние.

**Готово, когда:** тест проводит полную партию случайными допустимыми ходами до `MatchEnded` для 2–6 игроков без исключений и зависаний.

### Этап 4. Контент v1 (1 ч + фоновая генерация)

- [x] Схема JSON (предмет → 20 фактов с isTrue, difficulty, explanation).
- [x] `JsonSubjectProvider : ISubjectProvider` читает `Resources/Content/*.json`.
- [x] Тест-валидатор контента: 20 фактов, ровно 10/10, текст ≤ 90 символов, пояснение ≤ 120, уникальные Id, все символы есть в атласе шрифта.
- [x] Первые 4 предмета (осьминог, Эйфелева башня, кофе, Луна).
- [ ] Правдивые факты первых 4 предметов сверены по источникам вручную (ИИ проверил по своим знаниям, без поиска).
- [x] Атлас TMP с кириллицей и символами «»—…✓✗.
- [x] Фоном: ИИ генерирует черновики остальных 8 предметов (сверка — на этапе 12).

**Готово, когда:** валидатор зелёный, движок играет на настоящем контенте.

### Этап 5. Боты (1 ч)

- [x] `BotProfile` (знание по сложности, порог обвинения, шанс подмешать ✗) и три профиля: Осторожный, Наглый, Знаток.
- [x] `HeuristicBotStrategy : IBotStrategy` по алгоритму из первого документа (раздел 6). Порог растёт на 0,05 за каждый уже сделанный выстрел — чем ближе пуля, тем осторожнее бот.
- [x] Бот получает только `PlayerView`; «знание» факта детерминировано хэшем (бот, факт).
- [x] Тест-симуляция: 200 партий ботов, в лог — среднее число раундов, доля верных обвинений, победы по профилям.

**Готово, когда:** все 200 партий доигрываются; точная балансировка — на этапе 12.

### Этап 6. Сессия и серый стол (3,5 ч)

- [ ] Application: `IMatchSession`, `ISeatController`, `LocalMatchSession`, `LocalHumanSeat`, `BotSeat` (задержка 1–2,5 с через интерфейс таймера, а не корутины в ядре), `MatchFactory` для режима «С ботами».
- [ ] Presentation: `TablePresenter` + серые `TableView`, `SeatView` (имя, число карт, выстрелы x/6, жив/выбыл), `HandView` + `CardView` (выбор 1–2 карт), кнопки «Сыграть» и «Лжец!», текстовое окно проверки.
- [ ] Кнопки активны только тогда, когда действие допустимо (состояние берётся из `PlayerView`).
- [ ] `Bootstrap` собирает зависимости и запускает партию 1 человек + 3 бота.
- [ ] WebGL-сборка, полная партия в браузере, коммит + тег `day1`.

**Готово, когда:** в браузере можно сыграть партию против ботов до победителя без анимаций и красоты; Newtonsoft работает в сборке (при необходимости добавлен `link.xml`).

## День 2 — полировка, меню и hot-seat

### Этап 7. Навигация и меню (2 ч)

- [ ] `ScreenRouter` — конечный автомат: Splash → Menu → Rules → Setup / Lobby → Table → GameOver. У каждого экрана есть путь назад в меню.
- [ ] Splash: кнопка «Войти в бар» (первый клик разблокирует звук в браузере).
- [ ] Menu: «Играть с ботами», «На одном устройстве», «Онлайн» (до дня 3 — неактивна с подписью «скоро» или скрыта), «Правила», звук вкл/выкл.
- [ ] Rules: 3 карточки со свайпом — «Крупье даёт предмет и факты», «Ходи или кричи Лжец!», «Ошибся — играй в рулетку». При первом запуске показываются сами (`PlayerPrefs`).
- [ ] Setup: имя игрока, число ботов 1–5 (с ботами) или список имён 2–6 + «Добавить бота» (hot-seat). `MatchFactory` собирает сессию по `GameModeSettings`.
- [ ] Кнопка «Выйти в меню» за столом с подтверждением.

**Готово, когда:** из меню до первого хода — не больше 3 нажатий, ни одного экрана-тупика.

### Этап 8. Hot-seat (1,5 ч)

- [ ] `ViewerPolicy`: чья рука показана; в hot-seat — текущего человека только после подтверждения.
- [ ] `PassDeviceView`: «Передайте устройство: Лена» → «Я Лена, показать карты». Стол и сыгранные карты видны, рука скрыта.
- [ ] Заставка появляется перед выбором «Лжец! / Сыграть», а после хода рука сразу скрывается.
- [ ] Ходы ботов, проверка и рулетка идут без заставки.
- [ ] Ручной тест на 3 именах: чужая рука не появляется ни на один кадр (включая переходы и анимации раздачи).

**Готово, когда:** трое человек на одном телефоне доигрывают партию, не видя карт друг друга.

### Этап 9. Анимации и револьвер (2,5 ч)

- [ ] `AnimationQueue`: события проигрываются по очереди, `PlayerView` применяется после них; во время анимаций ввод заблокирован.
- [ ] Раздача: карты вылетают от крупье, предмет раунда появляется по центру стола.
- [ ] Ход: карты летят на стол; «Лжец!» — крупная надпись и тряска места обвинителя.
- [ ] `RevealOverlayView`: переворот карт с ✓/✗ и пояснением, кто играет в рулетку. В офлайне и hot-seat — кнопка «Далее», в онлайне — автопереход через 5 с.
- [ ] `RevolverView`: вращение барабана → пауза 1–1,5 с (напряжение) → щелчок пустой каморы или выстрел (вспышка, тряска экрана). Счётчик выстрелов x/6 у каждого игрока.
- [ ] Выбывание: место темнеет, игрок остаётся за столом как зритель.
- [ ] Подсветка чьего хода и подсказка «Выбери 1–2 карты или крикни Лжец!».

**Готово, когда:** по экрану без объяснений понятно, кто сходил, кто обвинил, что было правдой и чем кончилась рулетка; анимации не расходятся со состоянием.

### Этап 10. Финал и рестарт (1 ч)

- [ ] `MatchStats` в ядре: непойманные ✗, верные обвинения, пережитые выстрелы (считаются движком, а не UI).
- [ ] `GameOverView`: победитель и номинации «Лучший лжец», «Детектор лжи», «Борис хрен попадёшь». Ничья в номинации → все имена через запятую; нулевая статистика → номинация скрыта.
- [ ] «Сыграть ещё» — те же настройки, новые револьверы и предметы; «В меню».
- [ ] Предметы не повторяются между партиями одной сессии, пока не закончится пул.

**Готово, когда:** три партии подряд идут без перезагрузки страницы и без «хвостов» состояния от предыдущей.

### Этап 11. Визуал, звук, адаптив (1,5 ч)

Версия с заглушками подключена в сцене Boot через BarTheme.asset. [Инструкция по замене ресурсов и проверке на телефоне](<Этап 11 — подключение ресурсов.md>). Финальные материалы и ручная приёмка остаются открытыми.

- [ ] Стиль бара: тёмный фон, стол с сукном, карты-бланки, портреты-силуэты игроков, револьвер. Цвета и шрифты — в `UiTheme`.
- [ ] Адаптив: Canvas Scaler + два макета стола (горизонтальный и вертикальный), самый длинный факт влезает в карту на телефоне.
- [ ] Звуки через `ISoundPlayer`: клик, карта, «Лжец!», вращение барабана, щелчок револьвера, выстрел, победа. Источник — бесплатные звуки с лицензией CC0.

**Готово, когда:** игра выглядит цельной на ноутбуке и телефоне, нет серых заглушек.

### Этап 12. Контент v2, баланс, сборка (1,5 ч)

- [ ] Сверить и добавить оставшиеся 8 предметов (всего 12), валидатор зелёный.
- [ ] Прогнать симуляцию ботов: партия на 4 игрока — 8–14 раундов, ни один профиль не выигрывает больше 50 %. Подкрутить профили.
- [ ] 2 партии вручную против ботов: боты не выглядят ни тупыми, ни ясновидящими.
- [ ] WebGL на itch.io, проверка в Chrome, Safari и на телефоне, тег `day2`.

**Готово, когда:** офлайн-MVP с ботами и hot-seat можно сдать как есть. Это безопасная точка возврата.

## День 3 — онлайн и сдача

Если на этапе 1 онлайн вычеркнут, этапы 13–16 заменяются полировкой и дополнительным контентом, а этапы 17–18 остаются.

### Этап 13. Транспорт и комнаты (2,5 ч)

- [ ] `INetworkTransport` в Application: `SendToHost`, `SendToAll`, `SendToPlayer`, событие `MessageReceived(senderId, code, json)`.
- [ ] `PhotonTransport : INetworkTransport` (в Networking): `RaiseEvent` с кодами 1–5, `SendOptions.SendReliable`, полезная нагрузка — JSON-строка.
- [ ] DTO сообщений: `MatchStartMessage`, `ActionMessage`, `EventsMessage`, `ViewMessage`, `MatchAbortedMessage`; сериализация в одном месте (`MessageCodec`), тест «сериализация туда-обратно» для всех событий.
- [ ] `RoomService`: подключение, генерация 4-буквенного кода без похожих символов, `CreateRoom` (MaxPlayers 6, невидимая), `JoinRoom`, понятные тексты ошибок.
- [ ] Экраны: «Создать / Войти по коду», лобби (код крупно + кнопка «Скопировать», список игроков, у хоста — число ботов и «Начать»).

**Готово, когда:** три вкладки собираются в одном лобби по коду и видят одинаковый список игроков.

### Этап 14. Хост (2,5 ч)

- [ ] По «Начать»: `IsOpen = false`, хост назначает места (`ActorNumber` → `SeatId`, пустые — боты), шлёт `MatchStart`.
- [ ] Сессия хоста = `LocalMatchSession` + контроллеры: хост `LocalHumanSeat`, гости `RemoteSeat`, пустые `BotSeat`. Никакого отдельного сетевого движка.
- [ ] `RemoteSeat`: ждёт `ActionMessage` от своего `ActorNumber`, чужие и невалидные действия отбрасывает (проверка тем же `MatchEngine`).
- [ ] `NetworkBroadcaster`: после каждого действия — `Events` всем, затем `View` каждому гостю лично. В событиях нет чужих рук.
- [ ] `TurnTimer` (30 с) у хоста; таймаут → ход делает `IBotStrategy`. Остаток секунд — в `PlayerView`.
- [ ] Тест без сети: фейковый `LoopbackTransport` соединяет хоста и двух гостей в одном процессе и проводит партию.

**Готово, когда:** партия через `LoopbackTransport` доигрывается в тесте, а хост в браузере играет с ботами в созданной комнате.

### Этап 15. Гость (1,5 ч)

- [ ] `RemoteMatchSession : IMatchSession`: `Submit` → `ActionMessage` хосту; входящие `Events` и `View` → события сессии.
- [ ] Тот же `TablePresenter` и `AnimationQueue`, что в офлайне — без веток `if (online)` в Presentation.
- [ ] После отправки действия кнопки блокируются до ответа хоста (защита от двойного нажатия).
- [ ] Отрисовка таймера хода по данным из `PlayerView`.

**Готово, когда:** хост + 2 гостя в разных окнах доигрывают партию, у всех одинаковая картина стола, каждый видит только свои карты.

### Этап 16. Отключения (1 ч)

- [ ] Гость вышел в лобби → просто исчезает из списка.
- [ ] Гость вышел во время партии → хост меняет `RemoteSeat` на `BotSeat` (в том числе посреди его хода), всем тост «Марат ушёл, его заменил бот».
- [ ] Хост вышел → у гостей экран «Хост покинул игру» и возврат в меню.
- [ ] Потеря соединения с Photon (`OnDisconnected`) → сообщение и возврат в меню, без вечного ожидания.
- [ ] `Application.runInBackground = true`.

**Готово, когда:** закрытие любой вкладки в любой момент не оставляет остальных в зависшем состоянии.

### Этап 17. Тестирование (1,5 ч)

- [ ] Офлайн: 2 партии на компьютере, 1 на телефоне.
- [ ] Hot-seat: 1 партия на 3 имена + 1 бот.
- [ ] Онлайн: 3 окна + телефон; выход гостя посреди хода и посреди рулетки; выход хоста; таймаут хода.
- [ ] Пути назад: с каждого экрана в меню, «Сыграть ещё» во всех режимах.
- [ ] Все тесты ядра зелёные, консоль браузера без ошибок.
- [ ] Баги: сначала зависания и утечки чужих карт, потом визуал.

**Готово, когда:** чек-лист пройден без критических ошибок.

### Этап 18. Релиз и сдача (1 ч)

- [ ] Релизная WebGL-сборка (без Development Build), загрузка на itch.io, полноэкранный режим, обложка страницы.
- [ ] Инструкция для проверяющих на странице и в документе: один человек / компания с одним устройством / онлайн в нескольких окнах.

## Правила работы

**Git.** Один этап — минимум один коммит с номером этапа (`stage-03: MatchEngine + tests`). Теги `day1`, `day2`, `release` — точки, к которым можно откатиться.

**Вайбкодинг.**

- ИИ давайте один этап за раз: список задач этапа + спецификация правил + нужные интерфейсы из первого документа.
- Для ядра сначала просите тесты, потом реализацию: так сразу видно, что ИИ понял правила верно.
- Указывайте границы слоёв: «код в `LiarsBar.Core`, без UnityEngine», «вью без логики, только привязка данных».
- Полностью читайте код ядра и сети — именно там ошибка стоит дороже всего. UI можно проверять глазами в игре.

**Проверка каждого этапа.** Этап закрыт, только когда выполнено его «Готово, когда», тесты зелёные и есть коммит. Не начинайте следующий этап с незакрытыми критическими багами предыдущего.

**Сборки.** WebGL-сборка в конце каждого дня, а не только перед сдачей: ошибки вырезания кода, шрифтов и звука проявляются только в браузере.
