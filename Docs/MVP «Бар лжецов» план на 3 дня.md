# MVP «Бар лжецов»: план на 3 дня

Nov 19, 2026 · @Saylas

За 3 дня делаем WebGL-прототип на Unity 2D с тремя режимами: против ботов, hot-seat на одном устройстве и онлайн-комнаты на Photon PUN 2. Правила живут в одном чистом C#-ядре, режимы отличаются только источниками действий игроков.

## 1. Цель и объём MVP

Результат — ссылка на itch.io, по которой проверяющий сам проходит партию от меню до финала и может открыть онлайн-комнату в нескольких вкладках. Приоритет: сначала офлайн и hot-seat (они закрывают ТЗ), онлайн добавляется поверх готового ядра.

**Входит:**

- Режимы: «Играть с ботами» (1 человек + 1–5 ботов), «На одном устройстве» (2–6 людей, можно добавить ботов), «Онлайн» (создать / войти по коду, пустые места — боты).
- Экраны: загрузка, главное меню, правила (3 карточки), настройка игроков, лобби, стол, «передай устройство», проверка факта, финал.
- Полный цикл: раздача → ходы → «Лжец!» → проверка → русская рулетка→ выбывание → победитель → «Сыграть ещё» / «В меню».
- Контент: 12 предметов × 20 фактов (10 правдивых, 10 ложных) + короткое пояснение к каждому факту.
- Боты с тремя характерами (осторожный, наглый, знаток).
- Таймер хода в онлайне; автоход ботом при таймауте или отключении игрока.
- Минимальный звук (клик, переворот карты, выстрел, щелчёк револьвера если нет патрона), кнопка выключения звука.

**Не входит (следующие шаги):**

- Миграция хоста: если хост вышел, партия завершается с сообщением.
- Переподключение после перезагрузки страницы (место занимает бот).
- Защита от читерства: хост технически видит все руки.
- Аккаунты, рейтинги, тематические колоды, локализация.

## 2. Правила MVP (спецификация для кода)

Все числа вынесены в `GameRulesConfig`, чтобы баланс менялся без правки кода.

| Параметр | Значение |
| --- | --- |
| Игроки за столом | 2–6 (люди + боты) |
| Фактов у предмета | 20 (10 ✓ / 10 ✗) |
| Размер руки | 2–3 игрока: 5 · 4 игрока: 4 · 5–6 игроков: 3 |
| Состав руки | хотя бы 1 ✓ и 1 ✗ (пересдача, пока условие не выполнено) |
| Карт за ход | 1 или 2 |
| Пирожки | 6 на тарелке, 1 с перцем, позиция случайная и скрытая |
| Таймер хода | онлайн 30 с, офлайн и hot-seat — без таймера |
| Задержка бота | 1,0–2,5 с (чтобы ход было видно) |

**Партия:**

1. Каждому игроку — тарелка из 6 пирожков (позиция перца 0–5). Первый ходящий случайный.
2. **Раунд:** новый предмет (без повторов, пока не кончился пул), раздача живым игрокам. Владелец видит пометки ✓/✗ на своих картах.
3. **Ход:** если на столе есть ход предыдущего игрока, текущий выбирает «Лжец!» или «Сыграть 1–2 карты». Первый ход раунда — только сыграть. Карты кладутся текстом вверх, но без пометок.
4. Игроки с пустой рукой пропускаются. **Исключение:** если после хода карты не остались ни у кого, кроме сыгравшего, следующий живой игрок обязан крикнуть «Лжец!». Так раунд всегда заканчивается проверкой.
5. **Проверка:** вскрываются карты последнего хода. Хотя бы одна ✗ → в рулетку играет сыгравший; все ✓ → в рулетку играет обвинивший. На экране — пояснение к фактам.
6. **Русская рулетка****:** игрок нажимает спусковой крючок револьвера (индекс = число уже выстрелянных). Индекс = позиция пули→ игрок выбывает.
7. Живых игроков остался один → конец партии. Иначе новый раунд; начинает тот, кто ел пирожок (если выбыл — следующий живой).

**Финал:** победитель и номинации по статистике партии: «Лучший лжец» (больше всего непойманных ✗), «Детектор лжи» (больше верных обвинений), «Борис хрен попадешь» (больше всего раз играл в русскую рулетку не умирая).

## 4. Архитектура

Главная идея: **один движок правил для всех режимов**. Режимы отличаются только тем, кто управляет каждым местом за столом (человек на этом устройстве, бот или удалённый игрок) и где исполняется движок (локально или у хоста).

### Поток данных

```
Офлайн / hot-seat / хост онлайн:
  UI → Presenter → IMatchSession.Submit(action)
      → LocalMatchSession → MatchEngine.Apply(action)
      → GameEvent[] + MatchState → SnapshotFor(seat) → Presenter → View

Клиент онлайн:
  UI → Presenter → RemoteMatchSession.Submit(action)
      → PhotonTransport → [хост] RemoteSeatController → MatchEngine
      → [хост] NetworkBroadcaster → PhotonTransport (каждому свой снимок)
      → RemoteMatchSession → Presenter → View
```

### Core — правила (чистый C#)

- **Домен:** `Fact` (Id, Text, IsTrue, Explanation, Difficulty), `Subject`, `Hand`, `R``evo``lver`(BulletIndex, Shooted, `S``h``o``t``()` → попалась ли пуля), `PlayerState` (SeatId, Name, Hand, Revolver, IsAlive, Stats), `TablePlay` (кто и какие карты сыграл), `MatchState` (игроки, предмет, чей ход, фаза, последний ход).
- **Действия:** `IGameAction` → `PlayCardsAction(seatId, cardIds)`, `CallLiarAction(seatId)`.
- **События:** `RoundStarted`, `CardsPlayed`, `LiarCalled`, `FactsRevealed`, `R``e``v``o``l``ve``r``S``h``o``o``t``e``d`, `PlayerEliminated`, `TurnChanged`, `MatchEnded`.
- **Движок:** `MatchEngine` — единая точка входа (`Start`, `Apply`), внутри делегирует: `Dealer` (раздача с условием 1 ✓ + 1 ✗), `TurnOrder` (следующий живой с картами, принудительное обвинение), `AccusationResolver` (кто играет в рулетку), `IActionRule[]` (валидаторы хода).
- **Проекция:** `MatchState.SnapshotFor(seatId)` → `PlayerView`: публичное состояние + рука только этого игрока. Именно её видят UI, сеть и боты (бот не подглядывает в чужие карты).
- **Абстракции окружения:** `IRandom` (детерминированные тесты через seed), `ISubjectProvider` (откуда берутся предметы).
- **Боты:** `IBotStrategy.Decide(PlayerView, BotProfile, IRandom)` → `IGameAction`.

### Application — сессии и режимы

```csharp
public interface IMatchSession {
    event Action<PlayerView> ViewChanged;          // снимок для текущего зрителя
    event Action<IReadOnlyList<GameEvent>> EventsRaised;
    SeatId ViewerSeat { get; }
    void Submit(IGameAction action);
}

public interface ISeatController {               // кто управляет местом
    void RequestAction(PlayerView view, Action<IGameAction> submit);
    void Cancel();
}
```

- `LocalMatchSession` — держит `MatchEngine` и набор `ISeatController`. Используется в офлайне, hot-seat и у хоста онлайн.
- `RemoteMatchSession` — у клиента онлайн: движка нет, действия уходят хосту, снимки приходят от него.
- Контроллеры мест: `LocalHumanSeat` (ждёт нажатия в UI), `BotSeat` (вызывает `IBotStrategy` с задержкой), `RemoteSeat` (ждёт сообщение из сети, по таймауту передаёт ход боту).
- `ViewerPolicy` — чью руку показывать: в офлайне и онлайне всегда своё место; в hot-seat — текущего человека после экрана «передай устройство».
- `MatchFactory` — собирает сессию по `GameModeSettings` (режим, места, имена, боты).

### Presentation — MVP

- **View** (MonoBehaviour, без логики): `TableView`, `SeatView`, `HandView`, `CardView`, `R``e``v``o``l``v``e``r``V``ie``w`, `RevealOverlayView`, `PassDeviceView`, `GameOverView`.
- **Presenter** (обычный C#): `TablePresenter` подписан на `IMatchSession`, переводит снимок во вью-модели, кнопки вызывают `Submit`.
- `AnimationQueue` — события проигрываются по очереди, новый снимок применяется после анимаций. Иначе карта «исчезнет» раньше, чем долетит до стола.
- `ScreenRouter` — конечный автомат экранов: Menu → Rules → Setup / Lobby → Table → GameOver.

### SOLID

| Принцип | Где в проекте |
| --- | --- |
| SRP | `Dealer` только раздаёт, `AccusationResolver` только судит, View только рисует, Presenter только переводит |
| OCP | Новый режим = новая сборка контроллеров мест; новое правило хода = новый `IActionRule`; новый бот = новый `IBotStrategy` |
| LSP | Любой `ISeatController` и любая `IMatchSession` взаимозаменяемы — Presenter не знает режима |
| ISP | Узкие интерфейсы: `ISubjectProvider`, `IRandom`, `INetworkTransport`, `ISoundPlayer` |
| DIP | Core и Application зависят от абстракций; реализации (Photon, JSON, Unity Random) внедряются в `Bootstrap` |

### GRASP

| Шаблон | Где в проекте |
| --- | --- |
| Information Expert | `R``e``v``olver``.``S``hot``()` знает про пулю; `Hand` удаляет карты; `MatchState.SnapshotFor` знает, что скрыть |
| Creator | `Dealer` создаёт руки; `MatchFactory` создаёт сессии и контроллеры мест |
| Controller | `MatchEngine` — единственный вход для игровых действий; `ScreenRouter` — для навигации |
| Low Coupling | Core без Unity и Photon; режимы не знают друг о друге |
| High Cohesion | Сетевой код целиком в Networking, анимации — в Presentation |
| Polymorphism | `ISeatController` (человек / бот / удалённый), `IBotStrategy` (характеры ботов) вместо `switch` по типу |
| Pure Fabrication | `AccusationResolver`, `TurnOrder`, `AnimationQueue`, `NetworkBroadcaster` |
| Indirection | `INetworkTransport` между сессией и Photon |
| Protected Variations | Photon, источник контента и случайность спрятаны за интерфейсами — замена на Fusion или свой сервер не затронет правила |

**Задел на 3D-сиквел:** Core и Application переносятся без изменений, меняется только Presentation.

## 5. Режимы

| Режим | Сессия | Контроллеры мест | Чью руку видно |
| --- | --- | --- | --- |
| С ботами | `LocalMatchSession` | 1 × `LocalHumanSeat` + `BotSeat` | Всегда свою |
| Hot-seat | `LocalMatchSession` | N × `LocalHumanSeat` + `BotSeat` | Текущего человека после заставки |
| Онлайн, хост | `LocalMatchSession` + `NetworkBroadcaster` | хост `LocalHumanSeat`, гости `RemoteSeat`, пустые `BotSeat` | Свою |
| Онлайн, гость | `RemoteMatchSession` | — (движок у хоста) | Свою |

### Hot-seat

- Экран настройки: 2–6 имён + кнопка «Добавить бота».
- Перед ходом человека — заставка `PassDeviceView`: «Передайте устройство: Лена» → кнопка «Я Лена, показать карты». До нажатия рука скрыта, стол и сыгранные карты видны.
- Решение «Лжец!» принимает следующий игрок, поэтому заставка показывается до выбора, а не после.
- Ходы ботов и проверка проигрываются без заставки — это публичная информация.
- Если человек в hot-seat один (остальные боты), заставка не нужна — это режим «С ботами».

### Онлайн на Photon PUN 2

**Подключение и комнаты (`RoomService`):**

1. `PhotonNetwork.ConnectUsingSettings()`, фиксированный регион в PhotonServerSettings, `AppVersion` совпадает у всех сборок.
2. «Создать»: код из 4 букв без похожих символов (без O/0, I/1) → `CreateRoom(code, MaxPlayers = 6, IsVisible = false)`. Код занят → другой код.
3. «Войти»: `JoinRoom(code)`, ошибки — понятным текстом («Комната не найдена», «Игра уже идёт»).
4. Лобби: список игроков, хост выбирает число ботов и жмёт «Начать». После старта `IsOpen = false`.
5. Хост назначает места: `ActorNumber` → `SeatId`, оставшиеся места — боты.

**Сообщения (`PhotonTransport`, `RaiseEvent`, все надёжные, полезная нагрузка — JSON-строка):**

| Код | Сообщение | Кто → кому |
| --- | --- | --- |
| 1 | `MatchStart` (места, имена, настройки) | хост → всем |
| 2 | `Action` (`PlayCards` / `CallLiar`) | гость → хосту (`ReceiverGroup.MasterClient`) |
| 3 | `Events` (список публичных событий) | хост → всем |
| 4 | `View` (снимок с рукой получателя) | хост → каждому отдельно (`TargetActors`) |
| 5 | `MatchAborted` (причина) | хост → всем |

**Правила обмена:**

- Хост авторитарен: действие гостя проверяется тем же `MatchEngine` (чей ход, есть ли карты в руке), неверное отбрасывается.
- После каждого действия хост шлёт сначала `Events`, потом `View` каждому. Снимок целиком (несколько КБ), дельты не нужны — нет рассинхрона.
- В публичных событиях нет чужих рук. Пометки ✓/✗ приходят только в `FactsRevealed`.
- Таймер хода живёт у хоста (`TurnTimer`, 30 с); в снимке — остаток секунд для отрисовки. Таймаут → за игрока ходит `IBotStrategy`.

**Отключения:**

- Гость вышел (`OnPlayerLeftRoom`) → хост заменяет его `RemoteSeat` на `BotSeat`, всем тост «Марат ушёл, его заменил бот».
- Хост вышел (`OnMasterClientSwitched` у гостей) → экран «Хост покинул игру» и возврат в меню. Миграция хоста — вне MVP.
- `Application.runInBackground = true`, чтобы хост в фоновой вкладке продолжал отвечать. Для проверки в инструкции просить держать вкладку хоста в отдельном окне: браузеры замедляют таймеры фоновых вкладок.

## 6. Контент и боты

### Формат контента

```json
{
  "id": "octopus",
  "title": "Осьминог",
  "facts": [
    { "id": "octopus_01", "text": "У осьминога три сердца", "isTrue": true,
      "difficulty": 2, "explanation": "Два качают кровь через жабры, третье — по телу" },
    { "id": "octopus_02", "text": "Осьминоги живут в среднем 30 лет", "isTrue": false,
      "difficulty": 1, "explanation": "Большинство видов живут 1–2 года" }
  ]
}
```

**Требования к фактам:**

- До 90 символов (иначе не влезет на карту на телефоне), пояснение до 120.
- Правда — удивительная, ложь — правдоподобная. Из 10 ложных не больше 4 получены заменой числа, остальные — правдоподобные выдумки и распространённые мифы.
- Сложность 1–3 на каждом факте: по ней работают боты.
- Черновик делает ИИ, каждый правдивый факт проверяется вручную по источнику. Ошибка в ✓ ломает саму проверку.
- Предметы для MVP (12): осьминог, Эйфелева башня, кофе, Луна, шоколад, египетские пирамиды, кошки, Байкал, футбол, человеческий мозг, смартфон, пицца. Темы семейные и неспорные.

### Боты

Одна стратегия `HeuristicBotStrategy` + три профиля в ScriptableObject. Бот видит только свой `PlayerView`, как человек.

| Параметр | Осторожный | Наглый | Знаток |
| --- | --- | --- | --- |
| Знает факт сложности 1 / 2 / 3 | 70 / 45 / 20 % | 60 / 35 / 15 % | 90 / 70 / 45 % |
| Порог обвинения (оценка лжи) | 0,70 | 0,45 | 0,55 |
| Подмешать ✗ к ✓ в ходе из 2 карт | 10 % | 40 % | 20 % |

**Решение «Лжец!»:**

1. Обвинение принудительное → обвиняет.
2. Для каждой сыгранной карты: бот «знает» её с вероятностью из профиля. Выброс детерминирован по (бот, факт), чтобы бот не «забывал» факт. Знает → вероятность лжи 0 или 1; не знает → базовая 0,35.
3. Модификаторы базовой: +0,15, если у сыгравшего осталось ≤ 1 карты (его вероятно заставили соврать); +0,10 за ход из 2 карт.
4. P(ложь в ходе) = 1 − П(1 − pᵢ). Больше порога → обвиняет. Чем больше бот уже съел пирожков, тем выше порог (+0,05 за каждый).

**Решение «чем ходить»:**

1. Есть ✓ → играет 1 ✓; с вероятностью из профиля добавляет к ней ✗ «под прикрытием».
2. Только ✗ → играет одну, с самой высокой сложностью (её труднее разоблачить).

**Проверка баланса:** EditMode-тест прогоняет 200 партий «боты против ботов» и пишет в лог среднее число раундов, долю верных обвинений и победы по профилям. Цель: партия на 4 игроков — 8–14 раундов, ни один профиль не выигрывает больше 50 %.

## 7. План по дням

Расчёт на \~10 рабочих часов в день. Каждый день заканчивается рабочей WebGL-сборкой: если что-то сорвётся, есть что сдать. Ведите учёт времени с первого часа — его просит ТЗ.

### День 1 — ядро и играбельный офлайн (серые прямоугольники)

- [ ] **0:00–0:30** Проект Unity 6000.6.3f1 структура папок и asmdef, Git, пакеты (TMP, Newtonsoft, DOTween, PUN 2), AppId Photon.
- [ ] **0:30–1:30** Смоук-тест Photon: пустая сцена, создать / войти по коду, WebGL-сборка на скрытой странице itch.io, 2 вкладки + телефон. **Решение «делаем онлайн или нет» принимается здесь.**
- [ ] **1:30–4:30** Core: домен, `Dealer`, `TurnOrder`, `AccusationResolver`, `MatchEngine`, события, `SnapshotFor`. Тесты: раздача с условием, проверка в обе стороны, принудительное обвинение, русская рулетка, конец партии.
- [ ] **4:30–5:30** Загрузка контента (`JsonSubjectProvider`) + первые 4 предмета. Остальные генерируются параллельно.
- [ ] **5:30–6:30** `HeuristicBotStrategy`, `BotSeat` с задержкой, тест 200 партий ботов.
- [ ] **6:30–9:30** `LocalMatchSession`, `TablePresenter` + серый `TableView`: места, рука, кнопки «Сыграть» / «Лжец!», текст проверки, счётчики пирожков.
- [ ] **9:30–10:00** WebGL-сборка, партия от начала до конца против ботов. Тег `day1`.

**Итог дня:** игра против ботов работает целиком, пусть и без красоты; известно, работает ли Photon.

### День 2 — полировка, меню и hot-seat

- [ ] **0:00–2:00** `ScreenRouter`, главное меню, правила на 3 карточках, настройка игроков (имена, боты), `MatchFactory`.
- [ ] **2:00–3:30** Hot-seat: `ViewerPolicy`, `PassDeviceView`, проверка, что чужая рука нигде не мелькает.
- [ ] **3:30–6:00** `AnimationQueue` + DOTween: раздача, полёт карт на стол, крик «Лжец!», переворот с ✓/✗ и пояснением, револьвер(пауза → клик(пустой барабан) или выстрел пули), выбывание.
- [ ] **6:00–7:00** Финал: победитель, номинации, «Сыграть ещё» с теми же игроками / «В меню».
- [ ] **7:00–8:30** Визуальный стиль: фон бара, карты, тарелки, шрифты, адаптация под вертикальный и горизонтальный экран (Canvas Scaler + два макета стола), звуки.
- [ ] **8:30–9:30** Контент до 12 предметов, ручная сверка правдивых фактов, подстройка ботов по итогам симуляции.
- [ ] **9:30–10:00** WebGL на itch.io, проверка на телефоне. Тег `day2`.

**Итог дня:** готовый к сдаче MVP без онлайна — безопасная точка возврата.

### День 3 — онлайн и сдача

- [ ] **0:00–2:30** `PhotonTransport`, `RoomService`, коды комнат, экраны «Создать / Войти» и лобби.
- [ ] **2:30–5:00** Хост: сборка сессии с `RemoteSeat`, `NetworkBroadcaster` (события + снимки по игрокам), `TurnTimer`, валидация действий гостей.
- [ ] **5:00–6:30** Гость: `RemoteMatchSession`, приём событий и снимков через тот же `AnimationQueue`, отрисовка таймера.
- [ ] **6:30–7:30** Отключения: гость → бот, хост → экран «игра прервана», потеря связи с Photon → сообщение и возврат в меню.
- [ ] **7:30–9:00** Прогон: 3 вкладки + телефон, 3–4 полные партии, выход игрока посреди хода и посреди проверки, исправление багов.
- [ ] **9:00–10:00** Релизная сборка на itch.io, инструкция для проверяющих, учёт времени, инструменты и ограничения. Тег `release`.

**Итог дня:** MVP с тремя режимами и документацией для сдачи.

## 8. Риски, урезания и сдача

### Риски

| Риск | Как снизить |
| --- | --- |
| Photon не работает из РФ или в WebGL | Смоук-тест в первый час дня 1. Не работает → день 3 уходит на полировку, онлайн описывается как следующий шаг |
| Квадратики вместо кириллицы | Атлас TMP собрать в день 1 и прогнать через него весь JSON-контент |
| Newtonsoft падает в WebGL из-за вырезания кода | `link.xml` для сборок с DTO, Code Stripping: Low, проверка в сборке в конце дня 1 |
| Звук не играет в браузере | Браузеры требуют клика до звука: первый экран — кнопка «Войти в бар» |
| Длинные факты не влезают на карты | Лимит 90 символов в контенте + Auto Size в TMP + тест самого длинного факта на телефоне |
| Анимации расходятся со состоянием | Все изменения идут через `AnimationQueue`, снимок применяется после анимаций |
| Хост в фоновой вкладке тормозит | `runInBackground`, в инструкции — открывать хоста в отдельном окне |
| Не хватает времени | Резать по списку ниже, а не откладывать полировку |

### Что резать, если не успеваете (по порядку)

1. Номинации → только победитель.
2. Три профиля ботов → один.
3. Таймер хода в онлайне → без таймера (но замена ушедшего игрока ботом остаётся).
4. 12 предметов → 8.
5. Вертикальный макет → только горизонтальный (телефон поворачивают).
6. Онлайн целиком → сдать сборку `day2` и описать онлайн в документе.

### Критерии готовности (по ТЗ)

- [ ] Понятный вход: из меню до первого хода — не больше 3 нажатий, правила читаются за минуту.
- [ ] Партия проходится от начала до конца во всех трёх режимах.
- [ ] Финал с победителем и кнопки «Сыграть ещё» / «В меню».
- [ ] Контента хватает на 2–3 партии без повтора предметов.
- [ ] Нет тупиков: с любого экрана можно вернуться в меню, нет заглушек и пустых кнопок.
- [ ] Работает в Chrome и Safari на компьютере и телефоне, чужие карты нигде не видны.
- [ ] Тесты ядра зелёные.

### Что приложить к сдаче

1. **Ссылка** на скрытую страницу itch.io (+ репозиторий, если готовы показать код).
2. **Инструкция для проверяющих:**
   - один человек: «Играть с ботами»;
   - компания с одним устройством: «На одном устройстве»;
   - онлайн: «Создать комнату» в одном окне, «Войти по коду» в другом окне или на телефоне, пустые места займут боты.
3. **Время:** отдельно на идеи и на реализацию (по дням).
4. **Инструменты:** Unity 2022.3, Photon PUN 2, DOTween, ИИ-ассистент для кода и черновика контента.
5. **Известные ограничения:** выход хоста завершает партию; перезагрузка страницы не возвращает на место; хост технически видит все руки; контент — 12 предметов; первая загрузка на мобильном интернете может занять время.
